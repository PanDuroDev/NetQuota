# NetQuota roadmap

Status values are honest: `done` means implemented **and** exercised by tests or
by the documented manual procedure. Anything else says what is missing.

## v0.1 — foundation (this branch)

| Area | Status |
| --- | --- |
| Global network monitoring (interface counters, filter-layer de-dup, VPN separation) | done |
| Per-process ETW monitoring with PID-reuse handling | done (needs elevated service) |
| Application identity, publisher metadata, icon extraction | done |
| SQLite storage with migrations, hourly aggregation, backups | done |
| Quota model (daily/weekly/monthly/custom, per-direction, credits) | done |
| Quota engine with hysteresis and transitions | done |
| Firewall blocking with ownership manifest and recovery | done |
| Named pipe with explicit DACL, protocol validation | done |
| Windows service host, console mode, logging, auto-restore | done |
| Chrome MV3 extension: site ledger, DNR blocking, blocked page | done |
| Native messaging host with origin allow-list | done |
| Video adapters: YouTube (verified best-effort), TikTok, generic | done |
| Desktop UI | done (Tauri shell; see `apps/desktop/README.md`) |
| Installer / MSI, service registration UI | one-click install from the desktop app via UAC (`netquota-service --install`), plus scripts; MSI still missing |
| Speed limits (upload QoS) | stored, not enforced |
| Download shaping | unsupported, needs WFP driver |
| Automation rules UI | data model + engine present, UI minimal |
| Background-hours enforcement | stored, not applied |
| Localization (Arabic RTL / English LTR) | UI string table and direction switching done; messages generated by the service are English-only |
| CI on pull requests (tests, clippy, typecheck) | done |
| Windows binaries + extension zip built on GitHub | done (`build` workflow; no local 7 GB build needed) |

## v0.2 — control

- Elevated scenario test suite (`tests/` PowerShell harness) run on a VM.
- Automation rule editor bound to the existing `Rule`/`Trigger`/`Action` model.
- Scheduled background windows enforced by the engine.
- QoS upload throttling behind an explicit experimental flag.
- Notifications through the desktop app with per-app icons and action buttons.

## v0.3 — browser depth

- Twitch, Reddit, Instagram, X adapters with per-site verification.
- Better site estimation using `PerformanceObserver` long tasks and media
  session data where available.
- Per-site profile overrides (model exists, UI does not).

## v0.4 — shaping

- WFP callout driver for bidirectional per-app shaping, signed, with a watchdog
  that removes filters if the service stops.
- Only after a crash-safety design review.

## Later

- Per-user policies on multi-user machines.
- Additional operating systems behind the existing provider traits, with their
  own enforcement stories — not a port of Windows assumptions.

## Explicit non-goals

- Cloud accounts, sync, telemetry, ads.
- HTTPS interception or certificate installation.
- Killing processes to enforce quotas.
- Disabling Windows Firewall or modifying rules NetQuota does not own.
